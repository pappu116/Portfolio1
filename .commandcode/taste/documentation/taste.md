# Taste — Documentation
- Uses a strict "documentation-only" change mode: create the requested doc files, but never modify application source, tests, config, lockfiles, env files, or Git history; no staging/committing/pushing, no dependency changes, and no extra files beyond the ones explicitly listed. Confidence: 0.8
- Expects a conflict check before writing: if a target documentation file already exists, inspect it and stop for approval rather than overwriting existing content. Confidence: 0.8
- Prefers a fixed five-document set for a Next.js codebase: PROJECT_OVERVIEW (what it does, stack, architecture, what works vs incomplete), FILE_MAP (per-file responsibility, exports, callers, "when to open this file", directory tree), DATA_FLOWS (traced flows with error/fallback behavior), CODE_GLOSSARY (terms → real repo symbols), LEARNING_PATH (staged study plan) — with Mermaid diagrams and line numbers only where verified against the current file. Confidence: 0.75
- Wants documentation written for a beginner: every concept explained in plain Bengali with a real example from this repo, a verified file:line reference, and one sentence on when the concept is useful; no example code implying a feature exists when it doesn't. Confidence: 0.75
- Prefers learning-path docs structured as reading order → "go find this" → safe exercise → self-check questions, using the project's actual `package.json` scripts and non-destructive debugging exercises (curl against local routes, reading source) instead of edits to production logic. Confidence: 0.75
- Wants documentation to explicitly separate implemented behavior from planned features (side-by-side table) and to state limitations honestly — e.g. a contact API that returns `delivered: false`, a missing `public/` directory — rather than presenting plans as shipped. Confidence: 0.8
- Prefers lookups-oriented documentation: symptom → likely cause → file-to-open troubleshooting tables, plus a pre-edit checklist (where data comes from, where it is transformed, which component renders it, which test covers it). Confidence: 0.7
- Requires documentation to re-confirm claims against the current source before writing them, and to mark uncertain details as `যাচাই করা হয়নি` rather than asserting them. Confidence: 0.8
